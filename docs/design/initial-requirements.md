> [!IMPORTANT]
> 本書は実装前の初期案であり、内容を確約するものではありません。検証や実装を通じて
> 変更される可能性があります。実装と本書に差異がある場合は実装を正とし、差異が判明した

## 1. 目的

azkey のユーザーが識別子を入力すると、公開プロフィール情報を使った社員証風の
カード画像を生成し、その場で確認・ダウンロードできる Web サービスを提供する。

MVP では、一度生成してダウンロードするまでの短い操作を、ログインや専用アプリを
必要とせずブラウザだけで完結させる。画像はサーバーへ保存せず、生成リクエストの
応答に含める。ブラウザ上の表示とダウンロードは、ページを再読み込みまたは移動する
までの一時的な結果として扱う。

## 2. 前提と用語

- **azkey**: 本サービスが接続する Misskey 互換サーバー。MVP では単一の接続先を必須環境変数
  `AZKEY_BASE_URL` で固定する。利用者は接続先を指定できない。
- **ユーザー識別子**: `@username` 形式。先頭の `@` は必須とし、リモートホストを含む
  `@username@host` は MVP では受け付けない。
- **ノート数**: Misskey API の `notesCount`。画面や画像上では azkey で一般的な呼称が
  別にある場合、その表記へ変更する。
- 対象となるプロフィール情報は、認証なしで取得できる公開情報に限る。
- azkey 固有の API 差分が存在する可能性があるため、実装前に対象環境の `/api-doc` と
  実レスポンスを確認する。

## 3. 対象範囲

### 3.1 MVP に含めるもの

- ユーザー識別子を入力する単一ページのフォーム
- azkey API からの公開プロフィール取得
- アバター、表示名、ユーザー名、ノート数、生成日時を含むカード表面・裏面画像の生成
- 表面・裏面それぞれのプレビューと PNG ダウンロード
- 生成した表面・裏面 PNG のインメモリ応答とブラウザ上での一時表示
- 入力不備、ユーザー不在、上流障害、画像生成失敗の案内
- スマートフォンとデスクトップの主要ブラウザへの対応
- 基本的なアクセス制限、外部取得先の検証、タイムアウト
- ヘルスチェック、構造化ログ、最低限のメトリクス

### 3.2 MVP に含めないもの

- azkey アカウントでのログインや権限を要する情報の取得
- 生成履歴、ユーザー設定、テンプレート設定を保存するデータベース
- 複数のカードデザインを選ぶ機能
- ブラウザ上での自由配置、文字・色・画像の編集
- SNS への代理投稿
- 複数 azkey/Misskey インスタンスの任意指定
- 長期保管、公開ギャラリー、検索、ランキング
- 安定した URL や生成履歴のためのサーバー側画像保存
- 非同期ジョブキューやリアルタイム進捗表示

## 4. ユーザーフロー

1. 利用者がトップページを開く。
2. `@username` を入力して「カードを作る」を押す。
3. サーバーが入力を検証し、azkey から公開プロフィールとアバターを取得する。
4. サーバーがカード表面・裏面の PNG をメモリ上で生成し、両面を含む JSON 応答を返す。
5. ブラウザが各面の base64 データを Blob URL に変換し、表面・裏面のプレビューと個別のダウンロードボタンを表示する。
6. 利用者が必要な面の画像をダウンロードする。再読み込みまたはページ移動で表示中の結果は破棄される。

処理中は二重送信を防止し、操作が継続中であることを画面に示す。生成は同期処理とする。
処理時間に関する目標値は、対象環境での計測後に定める。

## 5. 機能要件

| ID | 要件 | MVP 受入条件 |
| --- | --- | --- |
| FR-001 | 識別子入力 | 前後空白を除去し、`@username` 形式・許可文字数以外は API を呼ばずエラーにする |
| FR-002 | ユーザー取得 | 設定済み azkey API から対象ユーザーを取得できる |
| FR-003 | 表示名決定 | `name` が空なら `username` を表示名として使う |
| FR-004 | アバター取得 | API が返した URL から制限付きで取得し、欠損時は既定画像を使う |
| FR-005 | 画像生成 | 同じ入力データと生成日時から、定義済みレイアウトの表面・裏面 PNG を1枚ずつ生成できる |
| FR-006 | 文字収容 | 長い表示名や Unicode を含む名前がカード領域をはみ出さない |
| FR-007 | プレビュー | 生成成功後、表面・裏面のカード全体をブラウザで確認できる |
| FR-008 | ダウンロード | 表面・裏面を個別のボタン操作で `.png` ファイルとして保存できる |
| FR-009 | 結果の一時性 | PNG はサーバーへ保存せず、ブラウザの Blob URL を再読み込み・ページ移動まで利用できる |
| FR-010 | エラー表示 | 入力不備、404相当、429、上流障害、タイムアウト、内部失敗を区別して案内する |
| FR-011 | 再試行 | エラー後も入力を保持し、利用者が修正または再試行できる |
| FR-012 | 多重送信防止 | 生成中は送信ボタンを無効にし、同じ画面からの意図しない連続送信を防ぐ |

### 5.1 画像仕様（MVP 方針）

- 形式: PNG、sRGB、静止画
- サイズと縦横比: 表面・裏面で同一とし、仮デザインは 1200 x 760（約 1.58:1）とする。正式デザインへの移行時に再確認する
- 掲載情報:
  - 円形または角丸のアバター
  - 表示名
  - `@username`（リモートユーザー対応時は `@username@host`）
  - ノート数（読みやすい桁区切り）
  - 生成日時
- 生成日時: `YYYY-MM-DD HH:mm TZ` の形式。タイムゾーンは運用設定に従う。
- フォント: リポジトリまたはコンテナへ同梱し、再現可能な描画にする。日本語、英数字、
  一般的な記号を表示できるものを選び、ライセンス表記を同梱する。
- 表示名が長い場合は、フォント縮小に下限を設け、それでも収まらなければ省略記号を付ける。
- アバターの透過、縦横比、巨大画像、壊れた画像を安全に処理する。

### 5.2 生成結果の応答契約

`POST /cards` は `application/x-www-form-urlencoded` の `username` フィールドを受け取り、
成功時は `200 application/json` で表面・裏面を同じ応答に含める。サーバーはこの応答を返すまで
PNG をメモリ上で保持するだけで、ファイルやデータベースへ保存しない。

```json
{
  "generatedAt": "2026-09-10T12:34:56.000Z",
  "cards": {
    "front": {
      "data": "<standard-base64-without-line-breaks>",
      "mediaType": "image/png",
      "fileName": "azkey-card-front.png"
    },
    "back": {
      "data": "<standard-base64-without-line-breaks>",
      "mediaType": "image/png",
      "fileName": "azkey-card-back.png"
    }
  }
}
```

`generatedAt` は UTC の ISO 8601 文字列とし、`mediaType` は MVP では `image/png` に固定する。
`data` は改行を含まない標準 base64 とする。ブラウザの最小限の Vanilla JavaScript は base64 を
デコードして `Blob` と `URL.createObjectURL` からプレビュー URL を作り、各 `fileName` を個別の
ダウンロードリンクへ設定する。表示更新時は古い URL を `URL.revokeObjectURL` で解放し、ページ
再読み込み・移動時には結果を保持しない。

失敗時は JSON の `{"error":{"code":"...","message":"..."}}` を返し、入力不備は 400、
ユーザー不在は 404、レート制限は 429、azkey の障害・タイムアウトは 502/504、画像生成失敗は
500 とする。`message` は利用者向けの安全な文面に限定し、内部例外や接続先を含めない。

### 5.3 仮デザインとデザインの受け渡し

MVP の仮デザインは、正式なブランドデザインと誤認されない中立的な見た目にする。

- 薄い無彩色の背景と白いカード面
- 左側にアバター、右側に表示名・ユーザー名・ノート数・生成日時
- 見出しは仮の `azkey MEMBER CARD` とし、正式ロゴは使わない
- 色、余白、各要素の座標をコード内へ散在させず、レンダラーの設定値としてまとめる
- デザイン変更で API クライアントや応答処理を変更しなくてよい構造にする

素材は `assets/card-templates/<template-name>/front` と `back` に分け、各面に `base.png`、
`icons/`、`value-frames/`、`icon-frames/` を配置する。`default` は差し替え用のダミー素材であり、
将来のテンプレート追加に備えた構成を先に用意する。MVP ではテンプレート選択 UI と実際の
テンプレート切り替えは対象外とする。

正式デザインへ更新する際の推奨受け渡し形式は、次の順とする。

1. Figma の閲覧リンクまたは編集可能な SVG と、出力サイズの完成見本 PNG
2. 出力サイズの PNG/JPEG 見本と、ロゴ・背景などの素材ファイル
3. 手描き、スクリーンショット、文章による配置指示

仮デザイン段階では 3 だけでもよく、追加資料なしで実装を開始できる。正式化するときは、
色コード、フォント名、余白、各要素の位置、長い名前の扱い、使用素材のライセンスを併せて
指定する。ロゴは可能なら SVG、写真・テクスチャは原寸以上の PNG/JPEG で受け取る。

## 6. 非機能要件

### 6.1 性能・可用性

- 性能目標は現時点では定めず、対象環境で処理時間と資源使用量を計測してから合意する。
- azkey API とアバター取得には接続・応答タイムアウトを設け、無期限に待機しない。
- MVP は生成 PNG をリクエスト処理中のメモリだけで扱い、再読み込みやページ移動で結果が失われることを許容する。
- API 障害時にプロセスを巻き込まず、利用者へ再試行可能なエラーを返す。

### 6.2 セキュリティ・プライバシー

- 入力値を URL やファイルパスとして直接使用しない。
- JSON 応答に `Cache-Control: no-store` と `X-Content-Type-Options: nosniff` を設定し、ブラウザや中間キャッシュに生成結果を残さない。
- API 接続先は `AZKEY_BASE_URL` で固定し、利用者に任意 URL を入力させない。
- アバター取得は `http`/`https` 以外を拒否し、許可ホスト、リダイレクト、解決先 IP、
  応答サイズ、MIME タイプ、画像ピクセル数を制限して SSRF と画像爆弾を防ぐ。
- IP 単位のレート制限を設ける。制限値は想定利用と運用データに基づいて設定する。
- 公開プロフィールであっても、通常ログへ表示名、完全な入力値、アバター URL を残さない。
- 生成 PNG はサーバーのファイル、データベース、バックアップへ保存しない。
- HTML 出力は自動エスケープし、CSRF 対策は Cookie セッションを使わない構成を前提に
  脅威モデルで再評価する。

### 6.3 アクセシビリティ・互換性

- キーボードだけで入力、生成、ダウンロードができる。
- 入力欄には可視ラベル、処理中表示には支援技術向け通知、エラーには修正方法を付ける。
- 色だけに依存して状態を伝えず、十分なコントラストを確保する。
- Chrome、Firefox、Safari、Edge、および主要なモバイルブラウザを対象候補とし、
  サポート範囲は動作検証後に定める。
- JavaScript が無効でも入力ページと説明を表示できる。生成結果の JSON 受信、Blob URL によるプレビュー、個別ダウンロードは JavaScript を使用する。

### 6.4 運用・保守性

- 設定は環境変数で注入し、シークレットをリポジトリへ保存しない。
- リクエスト ID、処理結果、処理時間、上流ステータスを JSON ログへ出す。
- リクエスト数、成功・失敗数、処理時間、上流 API 時間、画像生成処理時間を計測できる。
- 生存確認と準備完了確認の HTTP エンドポイントを持つ。
- 画像レイアウトはゴールデン画像またはスナップショットで回帰検証する。
- API クライアントと画像生成を Web 層から分離して単体テスト可能にする。

## 7. エラー時の利用者向け挙動

| 状況 | 表示方針 | HTTP の目安 |
| --- | --- | --- |
| 入力形式が不正 | 例を添えて入力欄付近へ表示 | 400 |
| ユーザーが存在しない | 「ユーザーが見つかりません」 | 404 |
| 利用回数超過 | 待ち時間を案内 | 429 |
| azkey が応答しない | 時間をおいて再試行するよう案内 | 502 / 504 |
| 画像生成に失敗 | 入力値を保持し、再試行を案内 | 500 |

内部例外、接続先、ファイルパス、スタックトレースは利用者へ表示しない。

## 8. MVP 完了条件

- 正常なユーザー、表示名なし、アバターなし、長い日本語名、絵文字を含む名前を生成できる。
- 存在しないユーザーと上流タイムアウトが意図した画面・ステータスになる。
- 表面・裏面の生成画像を主要なデスクトップ・モバイルブラウザで個別にプレビューし、PNG として保存できる。
- サーバーが表面・裏面を1回の JSON 応答で返し、ブラウザが両面をプレビューして個別に保存できる。
- 再読み込みまたはページ移動で、前回の生成結果が利用できなくなる。
- 入力検証、外部 HTTP 制限、パストラバーサル防止、レート制限を自動テストで確認できる。
- 画像生成の代表ケースがゴールデン画像テストを通る。
- コンテナを非 root ユーザー、読み取り専用ルートファイルシステムで起動できる。
